## 1. 프로젝트 개요

지원이 끝난 Notional V1에서, (1) `ExchangeRate`의 `int256` 절댓값 → `uint128` 변환이 경계값에서 어떻게 잘리는지, (2) 공개 ABI에 어떤 외부 함수가 남아 있는지, (3) 기능을 제한하는 업그레이드 시 저장 구조를 어떻게 비교해야 하는지를 직접 확인했습니다.

**확인된 사실 (출처)**

- V1 지원 종료 공지: 2022년 1월 31일까지 V1 지원을 끝내되, 출금 마감은 두지 않음. [V1 Deprecation Notice](https://blog.notional.finance/notional-v1-deprecation-notice/)
- 공식 사후 보고서: 2026-09-03경 V1 Escrow에서 약 **1.65M USDC + 69K DAI** 유출. 이후 V1 동작을 멈추는 업그레이드. 악용 계약 `0x9abd0b8868546105F6F48298eaDC1D9c82f7f683`. [Post-Mortem](https://blog.notional.finance/notional-v1-exploit-post-mortem/)
- OpenZeppelin 2020년 감사에서 unsafe cast를 L10으로 지적·SafeCast 권고. [OZ Notional Audit](https://www.openzeppelin.com/news/notional-audit)

**팀 해석:** “지원 종료일”만으로 보안 관리가 끝났다고 보기 어렵고, 남은 자산·호출 가능 함수·권한을 기준으로 종료를 정의해야 합니다.

## 3. 진행 방식

1. 기획서 확인 → GitHub `ExchangeRate.sol`·커밋 SHA 고정 → Escrow 프록시/구현체 Etherscan·Sourcify·RPC 확인  
2. Foundry 경계값 테스트 작성·실행 (`casting-boundary`, solc 0.8.24)  
3. Sourcify ABI 수집 + Python 분류 (`scripts/classify_abi.py`) + GitHub 소스 상태변화 검토  
4. Storage layout 최소 예제 (`Baseline` / `Restricted` / `Broken`) + `forge inspect` + diff 스크립트  
5. 로그·표·보고서·README 정리  

**도구·버전 (실측):** forge/cast **1.8.5**, solc **0.8.24**(테스트·layout), solc **0.6.12**(0.6 스니펫 빌드 성공), Python **3.13.5**, OZ contracts **v5.0.2**. 상세: `logs/tool_versions.txt`.

**역할**

| 담당 | 작업 |
| --- | --- |
| 이주호 | `ExchangeRate`의 `uint128(balance.abs())` 패턴을 따른 Foundry 경계값 테스트 작성·실행 (`casting-boundary/src/CastingHelper.sol`, `test/CastingBoundary.t.sol`), `forge test -vv` 로그·변환 결과 표 정리 |

| 김건우 | 공식 공지·사후 보고서·감사·GitHub 커밋 SHA·도구 버전 등 출처·수치 대조 (`logs/tool_versions.txt`, 보고서 사실/해석 구분) |

**1주차 확인 메모**

- `ExchangeRate.sol`은 **`uint128(balance.abs())`** 사용 (int128 아님). `pragma solidity ^0.6.0`. 동일 파일 계산 결과에는 `SafeCast.toUint128` 사용. 커밋 `4bf7a85e6cf81cde4283e0efab0b03f21249ba00`.
- Escrow 프록시: `InitializableAdminUpgradeabilityProxy` @ `0x9abd0b…f683`. EIP-1967 현재 구현체 `0x7885484Eb568275C45FFF07415c5430Dac682848` (Sourcify exact_match, verifiedAt 2026-09-04, pause/UUPS 형태 함수 5개). 이전 구현체 `0x8a134e651432A902041643668940C9a9cD270633` (Sourcify match, 함수 48개 — **분류에 사용**). Etherscan proxy upgrades 표: 2020-12-07 최초 Upgraded, 2026-09-04 pause tx `0x012fc554…`.
- Portfolios 등 현재 EIP-1967 구현체가 사고 직전 코드와 동일한지: **확인하지 못함** (공개 소스·Sourcify 기준으로만 분류, 보고서에 범위 표시).

## 5. 발견한 문제와 제약

- V1 원 코드는 `^0.6.0`이나 경계 테스트는 0.8.24에서 수행(명시적 축소는 0.8에서도 truncate). 0.6은 컴파일만 확인.
- Etherscan API v1 deprecated·v2 키 없음 → ABI는 Sourcify로 확보.
- Portfolios 등 **사고 직전 구현체 바이트코드 일치**는 확인하지 못함.
- Storage 비교는 최소 예제; V1 전체 컴파일·프록시 슬롯 매핑은 미실시.
- 함수 분류는 소스 검토 기반이며, 뷰/관리자 비중이 커 primary “기타·관리자”가 다수.
