# Constellation 연구 모델: 40%·60%

- 출처 ID: `team-research-40-60-v1`
- 반영일: 2026-11-11
- 프로젝트 리서치: 「솔라나 Constellation이 도입되면, 제재 거래는 어디서 막아야 할까」
- 리서치가 참조한 설계 문서: [Anza Constellation 백서](https://anza.xyz/constellationwhitepaper)
- 구현 버전: `0.2.0-research`, 비교 버전: `0.2.0-single-leader`

이 문서는 팀 리서치의 가정을 고정한 오프체인 모델입니다. Solana 메인넷 배포·공식 승인·거래 실행 성공을 뜻하지 않습니다. 확률·지연·암호학적 증명 생성은 모델링하지 않습니다.

## 입력과 판정 순서

- `attestationPercent`: 대상 거래가 담긴 pslice를 수신했다고 증명한 비율. 포함 의무의 기준은 **40% 이상**입니다.
- `attesterParticipationPercent`: 전체 증명 참여율. 유효한 집계의 기준은 **60% 이상**입니다. 두 비율은 같은 증명자 집합을 기준으로 하며 대상 묶음 증명률은 전체 참여율을 초과할 수 없습니다. 초과하면 `INVALID_SCENARIO`입니다.
- 수락 제안자와 제출 여부는 경로 존재를 뜻합니다. 한 제안자가 수락해도 증명 조건이나 실행 성공을 보장하지 않습니다.

1. 구조 오류는 400, 지원하지 않는 실행 버전은 422입니다. 새 버전의 전체 참여율 누락은 400이며 100%로 추정하지 않습니다.
2. 제안자 수·제출 경로·비율의 모순은 `INVALID_SCENARIO`, 블록 상태는 `NOT_EVALUATED`입니다.
3. 전체 참여율 <60이면 `BLOCK_SKIPPED`, 블록 상태 `SKIPPED`, 리더 제외 유효성은 null입니다. 경로가 없더라도 이 블록 전체 조건을 먼저 확인합니다. 이를 특정 거래 차단으로 해석하지 않습니다.
4. 참여율 >=60에서 제출 경로가 없으면 `NO_SUBMISSION_PATH`입니다.
5. 제출 경로가 있고 대상 묶음 증명률 <40이면 `INCLUSION_NOT_ENFORCED`입니다. 리더는 해당 묶음을 제외할 수 있습니다.
6. 대상 묶음 증명률 >=40이면 포함 의무가 있습니다. 데이터가 가용하면 `INCLUSION_ENFORCED`이며 리더가 제외를 시도하면 `leaderExclusionValid=false`, 블록 상태 `INVALID_LEADER_EXCLUSION`입니다. 제외 시도가 없으면 null, 블록 상태 `VALID`입니다.
7. 포함이 의무인 묶음이 가용하지 않으면 모델은 `BLOCK_SKIPPED`로 처리합니다. 포함 의무는 true로 보존하고 리더 제외 유효성은 null입니다. 데이터 부재를 선택적 제외 허가로 간주하지 않는 모델의 가정입니다.

단일 리더 비교 모델은 같은 제출 경로만 사용하고 Constellation의 두 비율·pslice 가용성으로 블록 유효성을 판단하지 않습니다. 블록 상태는 `NOT_EVALUATED`이며 지분별 리더 교체나 지연을 재현하지 않습니다.

## 버전과 기록

임계값은 런타임 환경 변수가 아닌 버전별 상수입니다. 결과의 `modelParameters`에 출처 ID와 40·60 기준을 보관합니다. 다른 기준으로 바꾸려면 새 모델 버전이 필요합니다. 요청 추적 ID가 달라도 동일 입력·버전은 같은 결과와 simulationId를 반환합니다.

과거 `0.1.0-draft`와 `0.1.0-single-leader` 결과는 당시 입력·결과 그대로 조회합니다. 이 버전으로 새 실험은 실행하지 않으며, 누락된 전체 참여율이나 과거 임계값을 새 규칙으로 채워 넣지 않습니다. 공통 JSON 봉투의 schemaVersion은 0.1.0을 유지하고 모델 버전에 따라 새 필드를 요구합니다.
