# 이상거래 발표자료

`index.html` 하나에 글꼴·그림·분석 결과를 포함한 발표자료입니다. 설명 페이지는 클릭할 때마다 정해진 다음 전개가 나타나는 선형 발표이고, 6페이지는 탐지 결과 데모이며, 8·11페이지는 설명을 마친 뒤 통제 실험 데모로 이어집니다. 실제 FE 컴포넌트와 내장 JSON을 사용하는 오프라인 상호작용입니다. 12개 주제 안에 35개 전개 상태가 있습니다. 설명과 데모 모두 HTML 하나로 실행되며 FE 서버·Backend·RPC 연결이 필요 없습니다. 모든 화면은 같은 밝은 바탕과 짙은 도식 영역을 사용합니다. 지갑·수신자·제재 목록의 역할, 관찰한 근거, 판정 결과를 그림 안에서 구분하고 각 전개에 짧은 해석을 함께 표시합니다. 제목은 명사형으로 통일했습니다.

## 발표 순서

개념 → 구현과 실제 사례 → 대응의 유효 범위 검증의 흐름입니다. 탐지·경로·모델 데모를 포함해 약 9분 45초 분량이며, 조작·전환을 포함해 11~13분을 목표로 합니다. 각 데모는 해당 개념을 설명한 뒤에만 등장합니다. 6페이지에서는 탐지 점수와 근거만 확인하고, 7페이지에서 처음으로 WARN·BLOCK 정책 판단을 공개합니다. 이후 Gateway와 Constellation은 동일한 제재 주소 BLOCK 요청을 이어서 사용합니다.

| 화면 | 제목 | 시간 |
| --- | --- | --- |
| 1 | 이상거래 | 20초 |
| 2 | 거래 흐름 분석 | 35초 |
| 3 | 탐지와 대응의 구분 | 35초 |
| 4 | 규칙 기반 탐지 | 40초 |
| 5 | 분산 송금 사례 | 1분 |
| 6 | 온체인 분석 시연 | 1분 20초 |
| 7 | 위험 신호와 정책 판단 | 45초 |
| 8 | 서비스 제출 통제 | 1분 15초 |
| 9 | 제출 경로의 차이 | 35초 |
| 10 | 증명 조건과 포함 의무 | 50초 |
| 11 | 블록 유효 조건 | 1분 15초 |
| 12 | 대응의 유효 범위 | 35초 |

Constellation은 실제 네트워크에서 잘 작동하는지를 입증하는 단계가 아닙니다. 팀 리서치의 40%·60% 규칙을 반영한 오프체인 모델에서 대응의 유효 범위를 검증합니다. 제출 경로, 묶음 포함 의무, 전체 참여 조건을 세 화면으로 나누어 설명합니다.

## 설명 뒤에 이어지는 세 데모

데이터와 결과는 `data/demo.json`을 HTML 내부의 JSON으로 포함하며, FE를 재사용한 코드·스타일·글꼴도 내장합니다. 네트워크는 `connect-src 'none'`으로 차단합니다. 새로운 수집·위험도·정책·프로토콜 계산을 하지 않습니다.

| 위치 | 설명과 시연 범위 | 연결 질문 |
| --- | --- | --- |
| 6페이지 | 분산 송금 35점·MEDIUM, 앞선 4건/전체 12건 근거, 정상 기준 0점·LOW 비교 | 이 위험 신호에 어떤 조치를 취해야 할까? |
| 7페이지 | 가상 1 SOL 요청에 WARN 적용 → 별도의 제재 주소 일치 BLOCK 소개 | BLOCK 결정은 어디에서 제출 중단으로 이어질까? |
| 8페이지 마지막 전개 (`#8.4`) | Gateway 설명 후 동일 BLOCK 요청의 정책 적용·미적용 경로를 직접 비교 | 다른 경로로 들어온 요청도 블록 구성 단계에서 제외할 수 있을까? |
| 9~11페이지 | 수락 경로 → 묶음 포함 의무 40% → 전체 참여 조건 60% | 선택적 제외와 블록 전체 건너뛰기는 어떻게 다른가? |
| 11페이지 마지막 전개 (`#11.3`) | 모든 조건 설명 후 저장된 5개 입력을 선택해 연구 모델·단일 리더 결과 비교 | 탐지와 대응의 유효 범위는 어디까지인가? |

첫 데모에는 정책 결과·제재 주소 사례·Gateway·Constellation 조작을 노출하지 않습니다. 정책 판단은 7페이지에서 새 단계로 시작합니다. Gateway는 설명 후 경로 버튼만 제공하며, Constellation은 증명·참여 조건을 설명한 후에만 선택할 수 있습니다. 데모마다 필요한 조작만 보이므로 뒷내용을 먼저 공개하거나 같은 설명을 반복하지 않습니다.

**6페이지 — 80초:** 분산 송금 결과 공개 20초 → 앞선 4건·전체 근거 40초 → 정상 기준 비교 10초 → 다음 질문으로 연결 10초. 시연은 기존 분석 결과를 확인하는 것으로 설명하며 새 서버 분석이라고 말하지 않습니다.

**8페이지 — 설명 후 30초:** 마지막 클릭으로 경로 비교 화면을 엽니다. 같은 1 SOL·정책 1.0.0·BLOCK 요청에서 경로만 바꿉니다. 정책 적용 경로는 제출 중단, 미적용 경로는 모의 제출 허용입니다. 이어 네트워크 포함 단계의 통제 가능성을 질문합니다.

**11페이지 — 설명 후 40초:** 마지막 클릭으로 5개 저장 조건을 선택합니다. 39.99%/40%와 참여율 60%/59.99%를 비교하되, 임의 조건을 입력하거나 결과를 새로 만들지 않습니다. 두 모델의 같은 입력을 나란히 보여줍니다.

각 데모의 상태는 독립적으로 유지되며 다른 페이지를 다녀와도 복원됩니다. **시연 처음으로**는 해당 데모의 기본 조건으로 돌아갑니다. 상단 **데모 초기화**는 현재 열린 데모만 초기화합니다. 조작 중 클릭·스크롤·방향키는 발표를 넘기지 않고, **하단 다음 단계 화살표**로 발표를 계속합니다. 설명 전개에서는 기존 클릭·휠·방향키 이동을 유지합니다. 인쇄 시 8·11페이지는 상호작용 직전의 설명 도식을 출력합니다.

정상 기준은 같은 정상 지갑의 조회 결과이며 정상 보장이나 불법성 판단은 아닙니다. 분산 송금의 전체 근거는 여러 유효 시간 창의 합집합이고, 제재 주소 사례의 조회 범위에는 자금 전송이 0건입니다. BLOCK의 근거는 주소 자체의 제재 레이블 일치입니다.

**검증:** 탐지 데모에서 정책·통제 조작이 노출되지 않는지, 근거 4건/12건 비교, 각 실험의 독립 실행·초기화·페이지 이동, 내장 데이터와 네트워크 차단을 확인합니다.

## 화면의 정보 배치

눈썹 제목, 도식 상단의 배지, 하단 조작 안내·진행 순서, 작은 출처·버전 문구는 본편에서 제거했습니다. 주요 제목·도식·판정·해석을 남기고, 작은 조건 각주 중 중요한 내용은 본문 해석에 합쳤습니다. 상세 출처·버전·조건은 출처 창과 발표 메모에서 확인합니다.

## 첫 페이지 자동 재생

첫 페이지는 거래 기록 → 탐지 → 정책 판단 → 서비스의 제출 통제 → 다른 경로의 가능성을 약 8초 동안 재생합니다. 탐지·판단·서비스 통제 지점에서 각각 약 1초씩 머문 뒤 다른 경로로 이어지며, 마지막 상태에서 약 3초간 대기한 뒤 처음부터 반복합니다. Home이나 첫 페이지 재진입으로 다시 재생합니다. 재생 중에도 클릭·오른쪽으로 다음 페이지로 넘어갈 수 있습니다. 첫 페이지를 벗어나면 재생을 중단합니다. 모션 끄기 또는 모션 줄이기 설정에서는 완성된 그림을 바로 표시합니다.

## 조작과 선형 전개

- 설명 본문 클릭 / Space / 오른쪽 / Page Down: 다음 전개 (데모가 열린 전개는 하단 화살표로 이동)
- 왼쪽 / Page Up: 직전 전개. 현재 주제의 첫 전개에서는 이전 주제의 마지막 전개로 복귀
- 휠 아래·위: 다음·이전 전개
- Home·End: 전체 발표의 처음·마지막 전개
- N: 현재 전개의 발표 메모, F: 전체 화면, M: 모션 전환, T: 12분 타이머

상호작용 데모를 제외한 설명 본문에는 조작할 선택지가 없습니다. 반복 송금·탐지 규칙·KYT/Policy/Gateway·실제 전송 근거·정책 결과·제출 경로·증명 조건은 미리 정한 순서로 진행합니다. 출처·발표 도구는 보조 창이며 발표 경로를 바꾸지 않습니다. 하단은 페이지 번호와 이동 화살표만 표시하며, 전개 번호는 발표 메모에서 확인합니다.

주소 `#5.3`은 5번째 주제의 3번째 전개를 뜻하며 `#5`는 그 주제의 첫 전개입니다. 정상 발표 중에는 주소를 직접 조작할 필요가 없습니다. 열린 창에서는 클릭·휠로 본문을 넘기지 않습니다. 긴 화면은 내용을 먼저 스크롤하며, 경계에서 새 휠 동작으로 전개를 전환합니다. 관성으로 여러 전개를 건너뛰지 않도록 했습니다.

발표 메모는 현재 전개에 맞는 설명 포인트와 주제 전체의 참고 설명을 함께 보여줍니다. PDF 인쇄는 각 주제의 마지막 전개와 연구 모델 비교표를 출력하고, 인쇄를 마치면 원래 전개 상태를 복원합니다.

## 데이터와 해석

메인넷 수집본 FIXTURE 분석 3건, 정책 판단 3건, 저장·재조회한 Gateway 2건과 Constellation 10건을 `data/demo.json`에 보관했습니다. HTML은 결과를 표시하며 위험도·정책·프로토콜 판정을 재계산하지 않습니다.

분산 송금 사례는 2026-11-09 00:00~03:00 UTC(종료 제외)의 거래 15건·전송 20건을 재분석한 결과입니다. 서버는 RAPID_FAN_OUT, 35점·MEDIUM을 반환했습니다. 각 클릭으로 누적하는 앞선 네 근거는 111초 안의 서로 다른 네 수신자입니다. 전체 근거 전송 12개·거래 서명 7개는 여러 유효 시간 창의 합집합이며 하나의 300초 구간에 있다는 뜻은 아닙니다. 급여·보상 지급도 같은 패턴일 수 있고 점수는 불법 가능성의 확률이 아닙니다.

가상 1 SOL 송금 요청의 정책 결과는 분산 송금 WARN, 제재 주소 레이블 직접 일치 BLOCK입니다. 제재 주소의 조회 범위에는 자금 전송이 0건이므로 실제 불법 송금 탐지 사례로 설명하지 않습니다. 동일 비교 지갑을 양쪽 평가에 사용한 ALLOW 기준 확인은 원본에만 보관합니다.

10화면은 리더의 제외 유효성을, 11화면은 전체 참여 조건을 분리해 표시합니다. 참여 기준 충족만으로 전체 블록이 유효하다는 뜻은 아닙니다. 60% 조건의 저장된 실행은 리더의 제외 시도 때문에 블록이 무효입니다. 상세 입력·판정·감사 ID와 추가 50%/60% 조건은 출처의 JSON과 인쇄 부록에 남겼습니다.

## 편집과 검증

- `src/deck.html`: 12개 화면과 도구
- `src/deck.css`: 밝은 본문·공통 도식 영역, 글꼴·탐색·인쇄
- `src/visuals.css`: 그림·상태·모션
- `src/deck.js`: 선형 상태 이동·클릭/휠/키보드·현재 전개 메모·출처·발표 도구
- `src/visuals.js`: 정해진 전개에 따른 그림·근거·서버 결과의 순차 표시
- `../apps/frontend/src/presentation/`: 발표 전용 분석실·내장 JSON·컴포넌트 테스트
- `vendor/offline-demo.js`, `vendor/offline-demo.css`: 실제 FE의 생성 번들
- `src/notes.json`: 주제별 설명, 35개 전개별 발표 포인트와 화면 해석
- `data/demo.json`: 서버 실행 결과

```sh
python presentation/export_data.py --backend http://127.0.0.1:8080
python presentation/build.py
python presentation/verify.py
```

HTML을 사용하는 데 서버나 빌드 도구는 필요 없습니다. `build.py`는 저장된 FE 번들을 사용해 HTML을 다시 조립합니다. FE 코드를 수정했다면 개발 컨테이너를 시작하고 `python3 presentation/build_demo.py`로 번들을 갱신한 뒤 HTML을 조립합니다. 일반 FE 빌드와 분리된 Vite `presentation` 모드를 사용합니다.

데이터 재수집은 개발 서버와 프로젝트의 계약 검증용 Python 환경이 필요합니다. 데이터 수집·검증에는 `jsonschema` 의존성이 필요하고, HTML 조립 자체는 표준 Python 3으로 실행합니다. 외부 출처와 실제 대시보드는 링크를 클릭할 때만 연결합니다. 데이터 재수집도 실제 Solana 거래를 전송하지 않습니다.
