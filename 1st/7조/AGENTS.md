# 에이전트 작업 지침

이 파일의 지침은 저장소 전체에 적용한다.

## 개발 기록

- 개발 중 확인되는 문제 사항이나 리서치 아이디어는 `docs` 폴더의 관련 문서에 기록한다.
- 관련 문서가 없으면 내용을 구분할 수 있는 이름의 Markdown 문서를 `docs` 폴더에 추가한다.

## 작업 브랜치

- 작업을 시작하기 전에 현재 Git 브랜치를 확인한다.
- `main` 브랜치에서 직접 파일을 변경하거나 커밋하지 않는다.
- `main` 브랜치에서 작업을 시작한 경우 변경 전에 작업 목적에 맞는 별도 브랜치를 생성하고 이동한다.
- 브랜치 이름은 `feat/기능명`, `fix/수정명`, `docs/문서명`, `chore/작업명`처럼 작업 유형과 목적이 드러나게 작성한다.

## 커밋 메시지 컨벤션

모든 커밋 메시지는 반드시 다음 구조를 따른다.

```text
유형(세부유형): 한국어 요약

- 한국어 본문
```

### 작성 규칙

- 제목은 반드시 `유형(세부유형): 한국어 요약` 형식으로 작성한다.
- `유형`과 `세부유형`은 영문 소문자를 사용한다.
- `세부유형`을 생략하지 않는다.
- 요약과 본문은 반드시 한국어로 작성한다.
- 제목 다음에 빈 줄을 한 줄 넣는다.
- 본문은 한 개 이상의 불릿으로 작성하고, 각 줄을 `- `로 시작한다.
- 모든 본문 불릿은 `추가`, `수정`, `개선`, `구성`과 같은 명사형으로 끝낸다.
- 본문에 불릿이 아닌 일반 문단을 작성하지 않는다.
- 하나의 커밋에는 서로 관련된 변경만 포함한다.

### 유형

- `feat`: 새로운 기능
- `fix`: 버그 수정
- `docs`: 문서 변경
- `refactor`: 동작을 바꾸지 않는 코드 구조 개선
- `test`: 테스트 추가 또는 수정
- `style`: 코드 동작과 무관한 형식 변경
- `build`: 빌드 시스템 또는 의존성 변경
- `ci`: CI/CD 설정 변경
- `chore`: 그 밖의 유지보수 작업

### 세부유형

변경 범위를 짧고 명확하게 표현한다. 저장소 공통 변경에는 `repo`, 각 애플리케이션 변경에는 `frontend`, `backend`, `contracts`를 우선 사용한다.

### 예시

```text
feat(frontend): 지갑 연결 화면 추가

- 사용자가 브라우저 지갑을 연결할 수 있는 버튼 추가
- 연결된 지갑 주소를 화면에 표시
```

## 초기 개발환경 파일 변경

- 현재 `frontend`, `backend`, `contracts`에 들어 있는 파일은 초기 개발환경을 위한 기본 스캐폴딩이다.
- 작업 목적에 맞는 구성이 필요하면 각 폴더의 기본 빌드 파일과 기본 생성 파일을 모두 삭제하고 새로 만들어도 된다.
- 여기에는 패키지 설정, 빌드 설정, 실행 래퍼, 기본 애플리케이션, 기본 테스트 및 예제 파일이 포함된다.
- 이후 실제 도메인 로직이나 사용자 작성 코드가 추가되면 해당 코드는 기본 스캐폴딩으로 간주하지 않는다.
