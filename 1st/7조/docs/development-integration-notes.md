# 개발 연동 기록

> 기준일: 2026-09-10
> 범위: 로컬 Anvil, 컨트랙트 배포, 프론트엔드·백엔드 연동

## CRB-INT-001 — 로컬 배포 후 거래 가능한 데모 상태 부족

- 상태: 해결
- 영향: 프론트엔드가 배포 직후 실제 투자·정산 흐름을 실행할 수 없었음
- 원인: 기존 배포 스크립트가 투자자에게만 mUSD를 지급하고 상품을 생성하지 않았음
- 처리: 별도 크리에이터 주소, 정산자 mUSD 잔액과 모집 중인 데모 상품 초기화 추가
- 검증: 배포 테스트와 Docker Anvil 상태 조회로 역할·잔액·상품 조건 확인

## CRB-INT-002 — 배포 주소와 ABI의 애플리케이션 공유 방식 부재

- 상태: 해결
- 영향: 프론트엔드에 하드코딩한 주소가 실제 배포 주소와 달라질 수 있음
- 처리: 로컬 배포 manifest 생성과 세 컨트랙트 ABI 추출을 하나의 명령으로 자동화
- 산출물: 프론트엔드와 백엔드의 생성 전용 컨트랙트 디렉터리에 동일한 주소·ABI 복사
- 후속 작업: 각 애플리케이션의 기존 하드코딩 설정을 생성 산출물 참조 방식으로 전환

## CRB-INT-003 — 프론트엔드 상품 상태와 컨트랙트 enum 불일치

- 상태: 해결
- 영향: 프론트엔드가 `Failed`, `Settling`, `Closed` 상태를 구분하지 못했음
- 처리: 컨트랙트 enum 값과 화면 표시 이름을 연결하는 공용 클라이언트 metadata 추가
- 추가 구성: 주요 custom error와 사용자 안내 메시지 매핑을 같은 metadata에 포함
- 검증: Foundry 테스트에서 여섯 개 상태 코드가 컨트랙트 enum 값과 일치하는지 확인

## CRB-INT-004 — 실제 RPC 전체 정상 흐름 자동화 부재

- 상태: 해결
- 영향: 애플리케이션 개발자가 역할별 호출 순서와 최종 잔액을 수동으로 검증해야 했음
- 처리: 새 데모 배포부터 투자·정산·종료·종료 후 청구까지 실행하는 단일 명령 추가
- 검증: 상품 `Closed`, 투자자 수익권과 청구액, 역할별 mUSD 잔액 및 Bridge 부채 0 확인

## CRB-INT-005 — 최초 접속 시 스타일 미적용 화면 노출

- 상태: 해결
- 영향: 브라우저가 스타일 없는 초기 HTML을 먼저 표시하고 외부 CDN 장애 시 화면 스타일이 계속 적용되지 않을 수 있음
- 원인: Tailwind CSS를 빌드에 포함하지 않고 본문 뒤의 `@tailwindcss/browser` 런타임 스크립트로 생성
- 처리: Tailwind CSS v4 PostCSS 플러그인과 정적 전역 CSS 빌드 구성으로 전환
- 검증: 최초 HTML의 CSS 링크가 Tailwind 유틸리티를 포함한 로컬 번들을 가리키고 외부 런타임 스크립트가 제거됐는지 확인

## CRB-INT-006 — 페이지와 공통 화면 골격 결합

- 상태: 해결
- 영향: 헤더와 모바일 탐색이 메인 페이지에 직접 구현되어 다른 화면에서 재사용하거나 독립적으로 수정하기 어려웠음
- 처리: 브랜드·탐색·지갑 영역을 `Header`로 분리하고 저작권 정보를 포함한 `Footer` 추가
- 화면 구성: 콘텐츠 영역은 순백색으로 유지하고 기존 연회색 배경을 헤더와 푸터에 적용

## CRB-INT-007 — 운영 상품 catalog와 온체인 상품 부재

- 상태: 해결
- 문제: 백엔드는 단일 classpath JSON만 제공하고 프론트엔드는 조회 실패 시 코드에 포함된 목업 상품을 노출
- 처리: PostgreSQL과 Flyway 기반 상품·정산 기간 schema, 세 개의 초기 Base Sepolia 데모 상품, 상품 목록 API 구성
- 온체인: Base Sepolia `RevenueBridge`에 상품 ID `1`부터 `3`까지 등록하고 DB의 금액·일정 mirror를 실제 트랜잭션과 일치하도록 구성
- 데모 만기: 세 번째 상품에 환경 변수로 조절 가능한 단축 모집·수익·정산 기간 적용
- 보안: 운영 서버에는 배포 개인키를 저장하지 않고 개발 PC의 Foundry script에서 issuer 트랜잭션 실행

## CRB-INT-008 — 즉시 만기 데모 상품 이미지 응답 실패

- 상태: 해결
- 문제: 세 번째 데모 상품이 참조하던 외부 Unsplash 이미지가 `404`를 반환해 상품 카드 이미지가 표시되지 않음
- 처리: 외부 URL 의존성을 제거하고 프론트엔드 정적 SVG 자산과 기존 DB 값을 갱신하는 Flyway migration 추가

## CRB-INT-009 — 정상 흐름 자동화와 웹 시연의 단절

- 상태: 해결
- 문제: 기존 정상 흐름 스크립트는 모든 트랜잭션과 시간 이동을 한 번에 처리해 웹 화면에서 단계별 상태 변화를 설명하기 어려움
- 처리: Anvil 전용 데모 덱에서 모집 완료, 확정·선지급, 세 차례 정산, 만기, 수익 청구를 버튼 단위로 실행하도록 구성
- 격리: `DEMO_CONTROL_ENABLED=true`와 로컬 체인 ID `31337`을 모두 만족할 때만 제어 API를 활성화하고 Base Sepolia에서는 차단
- 반복 시연: 고정 Factory가 새 mUSD·Bridge·수익권 토큰과 초기 상품 세 건을 배포하고 프론트엔드가 활성 주소를 자동 추적하도록 구성
- 운영 초기화: Base Sepolia에서는 Factory 소유자 지갑이 재배포 트랜잭션에 서명하며 운영 서버와 프론트엔드에 개인키를 저장하지 않도록 구성
- 기록 보존: 초기화 전 계약과 거래 기록은 체인에 그대로 남고 서비스가 참조하는 활성 계약 주소만 새 버전으로 전환
- 배포 크기: Bridge 내부 토큰 배포 코드를 별도 Factory로 분리해 EIP-170 계약 런타임 크기 제한 준수

## CRB-INT-010 — 토큰 승인 완료를 투자 완료로 잘못 표시

- 상태: 해결
- 문제: 최초 투자에서 mUSD 사용 승인 트랜잭션만 확정돼도 완료 문구가 표시되고 실제 투자와 모집 현황 갱신은 실행되지 않음
- 처리: 승인과 투자를 단일 화면 흐름으로 연결하고 투자 영수증이 확정된 뒤에만 완료 문구 표시
- 동기화: 투자 확정 직후 상품·승인 한도와 공용 온체인 조회 캐시를 갱신해 상품 카드의 모집 현황에 즉시 반영

## CRB-INT-011 — 투자 판단 정보와 지갑 동작의 시각적 우선순위 부족

- 상태: 해결
- 문제: 상품 카드가 수익 배분율과 만기일을 먼저 강조해 현재 모집액·목표액·모집 마감을 빠르게 비교하기 어려웠고 지갑 관련 동작이 헤더에 분산됨
- 처리: 상품 카드와 상세 화면의 정보 순서를 모집 상태, 상품 정체성, 모집액·진행률, 투자 조건·일정 순으로 통일
- 서체: Pretendard Variable을 자체 호스팅하고 금액·구좌·비율에 고정 폭 숫자와 한국어 천 단위 구분 적용
- 지갑: 헤더에는 연결 상태·잔액·주소만 요약하고 네트워크 전환, 테스트 자산 충전, 주소 복사, 연결 해제를 지갑 메뉴로 통합

## CRB-INT-012 — 홈과 주요 기능이 단일 탭 상태에 결합

- 상태: 해결
- 문제: 루트 화면이 마켓플레이스와 포트폴리오 탭 상태를 직접 관리해 개별 화면 URL 공유와 브라우저 탐색이 불가능함
- 처리: 루트는 서비스 소개와 주요 진입 동작을 제공하는 전용 히어로 화면으로 변경
- 라우팅: 마켓플레이스와 포트폴리오를 각각 `/marketplace`, `/portfolio` 페이지로 분리하고 공통 레이아웃에서 헤더·푸터·데모 패널 제공

## CRB-INT-013 — Base Sepolia 운영 화면의 단계별 시연 기능 부재

- 상태: 해결
- 문제: 운영 화면에서는 Factory 초기화만 가능하고 모집, 선지급, 정산, 만기, 청구 상태를 단계별로 시연할 수 없었음
- 권한: Factory 소유자 지갑을 연결한 경우에만 운영 데모 덱을 제공하고 모든 쓰기 작업은 MetaMask에서 직접 서명
- 시나리오: 단축 일정 상품 ID 3을 대상으로 모집 완료, 확정·선지급, 세 차례 정산, 만기, 수익 청구를 순서대로 실행
- 시간 제약: 공개 테스트넷의 블록 시간은 변경하지 않고 다음 정산 가능 시각까지 남은 시간을 화면에 표시
- 초기 상태: 기존 Base Sepolia v1 배포에는 데모 투자자 권한과 잔액이 없어 Factory 초기화를 먼저 안내

## CRB-INT-014 — 화면 간 온체인 상태 갱신 지연

- 상태: 해결
- 문제: 투자 또는 수익금 청구 트랜잭션이 확정돼도 지갑 잔액과 열린 데모 덱이 이전 상태를 유지해 수동 새로고침이 필요함
- 처리: 투자·청구·데모 단계 확정 후 공통 체인 상태 변경 이벤트를 발행하고 지갑, 상품 목록, 로컬·운영 데모 덱이 즉시 재조회하도록 구성
- 보정: 다른 브라우저나 외부 트랜잭션도 반영할 수 있도록 주요 온체인 조회에 5초 간격 갱신 추가
- 필터: 마켓플레이스 상태 필터를 백엔드 초기 상태가 아닌 실시간 온체인 상태 기준으로 변경

## CRB-INT-015 — 상품 상세 딥링크와 운영 제어 UI 불일치

- 상태: 해결
- 문제: 수익권 metadata가 더 이상 상세 화면을 열지 않는 루트 URL을 가리키고 운영 데모 덱 버튼과 지갑 브라우저 알림이 일반 화면에 노출됨
- 딥링크: metadata 주소를 `/marketplace?offering={id}`로 변경하고 URL 진입·뒤로 가기·닫기 동작을 상세 모달과 연결
- 운영 UI: Base Sepolia 데모 덱 버튼은 Factory 소유자 지갑 연결 시에만 표시하고 지갑 알림은 화면 내 토스트로 통일
